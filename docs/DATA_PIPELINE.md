# 数据流水线与 100K SFT 生成规范

> 历史设计规范，不是实际执行验收记录。正式实验改为复用公开 SFT 参考答案，未完成此处要求的全面人工审核和跨源作品隔离核验。实际数据、数量和限制以仓库 README 为准；正式来源入口为 production_cpt_sources.yaml 和 production_sft_sources.yaml。

本项目把“有人工/公开参考答案的数据”和“教师模型合成的数据”分开保存、分开统计。合成答案不会因为通过规则检查就被视作人工真值。

## 1. 原始数据与许可

`configs/data/sources.yaml` 是唯一采集入口。每个来源都记录 dataset、config、split、license 和 revision。当前启用：gujilab 古籍/翻译/标点（CC0-1.0）、FineWeb-2 中文和 FineWeb 英文（ODC-By-1.0）。CCI3-HQ 需要接受用户协议，因此默认关闭。原始文件逐条保留 dataset、source_id、license 和 metadata。

## 2. 规范化、过滤与去重

1. 仅做 Unicode NFC、空白和换行整理，不进行繁简转换，不替换异体字。
2. 质量规则检查长度、乱码替代符、连续重复字符、网页模板、重复行和中文比例；拒绝原因进入 `audit.json`。
3. 先对规范文本做 SHA-256 精确去重，再用字符三元组 SimHash（64 位、汉明距离不超过 3）做近重复去重。
4. 以作品名优先，其次 source_group/source_id/URL/id 为组键；同一作品只能进入 train、validation、test 中的一个，防止章节泄漏。

## 3. 增量预训练混配

长文先用目标模型 tokenizer 切成最多 2,048 token 的块；CPT 训练时各文档间插入 EOS。混配器按实测模型 token 而不是字数采样，最后一个块按剩余配额截断。默认研究配比是古文 20%、通用中文 60%、通用英文 15%、理工技术 5%。样本实测因尚无独立理工源，使用 20/65/15；100K token 清单精确记录为 20,000/65,000/15,000。

不允许把同一文档无限复制来凑 40B：默认最多复用两轮，不足即报错。40B 配置仅用于集群；本地版本应从 50M token 起做 5%/20%/50% 古文比例消融，再按资源扩展到 200M 和 500M。

## 4. 100K SFT 数据如何产生

目标训练条数：双向翻译 50K、翻译与鉴赏 25K、约束创作/运用 25K。

- 双向翻译：优先读取公开的 source-reference 对。方向由数据字段决定；不通过长度比、空值和重复检查的样本删除。训练配额恰为目标值，验证/测试另算。
- 鉴赏：从仅属于古文类别、中文字符占比至少 65% 的 held-in 原文切片。教师必须先翻译，再给出带原文片段的分析。规则要求长度正常并至少匹配一个连续四字原文片段。
- 创作：从古文主题和意象生成带明确体裁/长度/关键词约束的任务。规则拒绝与来源连续八字相同的答案，减少照抄。
- 教师输出：`synthesize-sft` 使用确定性解码，同时写 `audit.jsonl` 和 `accepted_candidates.jsonl`。每条记录带 teacher_model、生成参数、来源、规则结果和 `requires_human_review=true`。
- 人工复核：至少按任务、来源、长度分层抽检；0.5B 本地教师只用于验证流水线，不建议直接承担正式 50K 合成标注。未完成复核的行不得复制到 `data/final/sft`。

## 5. 20K 偏好数据

从已复核 SFT 参考答案取 chosen。rejected 优先采用同一策略模型的多次采样并由人工/奖励规则标错；缺少采样时，代码构造可审计的困难负例：否定翻转、数字替换、信息遗漏、现代口吻侵入或截断。每条偏好对记录错误类型，不复制样本凑数。RM、DPO、GRPO 使用同一问题集合和同一 split，保证算法比较公平。

## 6. 正式评测隔离

最终 4×100 题必须来自从未进入 CPT/SFT/偏好训练的作品组，并带人工参考答案和评分量表。`build-eval` 只接受 `split=test`，任何任务不足 100 条都会报错，不会从训练集补齐。通用中文、英文和古文困惑度数据也需固定后再开始训练。
